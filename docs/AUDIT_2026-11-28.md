## 4. Security review

Reviewed in code and with the database checks. HTTP-level tests were not run.

**Critical (cross-user access, key exposure, injection): none found.** This is a finding from review plus the ten database checks, not proof. The HTTP checks above are the missing proof.

Because the shipment status is derived from those values, a user can make their own shipment show "AI pre-cleared" without real approvals. Effect: only their own data, an internal label. ## 5. Product improvement assessment: Disruption Impact Summary

The simulator's result already includes before and after totals and the added days, cost and risk, and the summary card already shows them with a status banner, the server's explanation, both routes, and the "illustrative data" notice. What was missing was one sentence that says it plainly. PR #45 adds `impactHeadline()` (frontend only, from the existing numbers, no new calculation, no AI, no dependency, no backend change) and shows it in the banner, for example: "An alternative route exists. Estimated impact: 2.3 days longer, $410 more freight cost, risk score up 1.3." Other outcomes (unaffected, no alternative, closed origin or destination) get honest one-line wording. Four tests cover it. It has not been seen in a browser.
